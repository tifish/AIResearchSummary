传统语音代理要串联语音转文字、推理模型和文字转语音。每次交接都会增加延迟，也可能破坏对话节奏。

GPT‑Live‑1 用单一模型同时处理听与说。它可以即时应对打断和简短回应，并把深度推理交给后端。

自然语音体验不仅取决于声音，还取决于系统能否判断何时回应、何时等待。

这种分工让开发者能按任务调整推理深度、速度和成本。

我们正在 API 中推出 GPT‑Live‑1。这款功能强大、对话自然的语音模型，可帮助开发者构建支持语音的应用和业务工作流。GPT‑Live‑1 最早在 ChatGPT 中推出，能够同时听与说。正如在 Codex 和 ChatGPT Work 中展示的那样，它可以将更深入的推理和行动委派给与之配合的模型和工具。

此次 GPT‑Live‑1 的 API 版本重点加入了新的能力。开发者可以围绕自己的用户、工作流和目标，引导并定制语音体验。流畅处理打断是 GPT‑Live‑1 的核心优势之一，也已开始产生业务价值。在早期评估中，Speak 发现，GPT‑Live‑1 会在语言导师回应前给学习者更多思考时间。与此前基于轮次的系统相比，打断减少了近 80%。

GPT‑Live‑1 在 API 中的主要优势：

  • 打断处理：单一模型同时对输入和输出音频进行推理，从而更好地处理打断。这样可以避免语音转文字—大语言模型—文字转语音（STT–LLM–TTS）串联架构带来的延迟，以及交接环节的不稳定。
  • 推理与工具调用委派：GPT‑Live‑1 可以将推理和工具调用委派给 GPT‑6 Astra 这样的后端文本模型，也可以交给第三方模型。
  • 语气、语速和风格：开发者可以通过系统提示词，塑造代理的语气、语速和对话风格。
  • 静默上下文管理与背景噪声处理：更好地应对背景噪声和静默，不打断对话，也不把每一步都说出来。
  • 长时间会话的可靠性：在较长的互动过程中，更好地保留上下文并维持对话质量。
  • 电话支持：支持部署用于电话通话的全双工语音代理，适用于餐厅预订、客户支持等场景。

简化语音代理架构，降低语音延迟

传统语音代理会把语音转文字、推理模型和文字转语音串联起来。每一次交接都会增加延迟。对话的时机、上下文或自然节奏也更容易在交接中丢失。协调这些阶段的工作通常落在开发者身上。用户打断、停顿或改变话题时该如何处理，也需要他们安排。

GPT‑Live‑1 在单一模型中处理听与说，简化了语音层。它可以即时回应打断和简短回应，同时把更深入的推理委派给后端。这样，后台处理任务时，对话仍可继续。

“与我们原来的级联实现相比，GPT‑Live‑1 让代码库缩减了 80%，删除了 2.3 万行代码。这让我们能够与患者进行自然的实时对话。团队也腾出了精力，去改善从预约到就医指引的整个体验。”

开发者可以自行选择对话背后的模型、工具和代理运行框架。例如，可以为 GPT‑Live‑1 搭配 Luna 这样的模型，处理排期或订单更新等高频任务。对于需要推理的复杂客户问题，则可以使用 Astra 这样的模型。这种灵活性让开发者能够针对每项任务，选择合适的推理深度、速度和成本。

GPT‑Live‑1 原生提供自动语音识别（ASR）转写文本和回复文本。它对字母与数字内容也有较强的理解能力，并支持关键词偏置。虽然 GPT‑Live‑1 不是基于轮次的模型，但它原生支持轮次检测。因此，开发者仍可围绕明确的轮次边界构建应用。
