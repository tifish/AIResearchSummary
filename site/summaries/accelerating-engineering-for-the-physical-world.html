最值得带走的洞见

  1. AI 已能参与跨专业设计。设备原型将机械、电气和软件工作连接在同一流程中。
  2. 使用增长与效果提升应分开看。23 倍衡量的是 token 用量，而非工程效率。
  3. 评测进步具有明确范围。BenchCAD 2.0 提供部分工程任务的能力证据，不能覆盖整个工程生命周期。
  4. 制造落地仍依赖专家验证。公差、装配、准确性和可制造性都是实际部署中的检查重点。
  5. 更多设计选择可能比单纯提速更有价值。Mazda 的试点着重探索造型与空气动力学性能如何兼顾。

今天，我们分享 OpenAI 模型在帮助工程师设计、仿真和制造实体产品方面取得的进展。这些能力覆盖机械工程、电气工程和端到端系统设计。它们已经在帮助我们的内部团队测试想法，并加快迭代。

在这些项目中，工程师需要借助专业工具，将机械设计、电子系统、软件和制造要求结合起来。我们正在训练模型，为这些工作提供支持。从准备图纸、设置仿真，到协调不同专业之间的变更，都在支持范围之内。我们的目标是让工程师有更多时间探索想法、改进设计。

过去一年，前沿模型能力的提升帮助内部团队更快地测试新想法并开展迭代。我们也看到了早期证据，表明这些能力正在改善行业中的专业工作流程。我们正与合作方一起研究，这些能力在哪些方面最能发挥作用，以及还有哪些地方需要改进。如果你是工程师、工程公司或软件供应商，参与复杂实体产品的设计、仿真、制造或生产，我们期待与你合作。我们希望围绕你使用的工具和需要解决的问题，共同推进这项工作。

用 Astra 设计设备

我们通过一项测试，检验 Astra 在多模态和计算机操作工作流中的领先表现：能否在没有任何人工直接编辑的情况下创建设备。为此，我们使用 GPT‑6 定义功能需求，并设计外壳、印刷电路板（PCB）及所需的软件集成。最终设备让用户能够与 Codex 对话。

  • 美学与外观设计：Astra 设计了设备外观。它参考了我们近期与 Work Louder 的合作，也从游戏和玩具中汲取了灵感。（在新窗口中打开）
  • 机械设计：Astra 设计了外壳，以及用于固定组件的内部结构。（在新窗口中打开）
  • 电气设计：Astra 选择了电子元件，并设计了印刷电路板（PCB）。设计涵盖元件布局和连接方式，以便将电路板装入外壳。
  • UI/UX 与软件：Astra 设计了用户界面，并生成了将设备连接到 Codex 所需的固件和软件集成。

两名团队成员将这项工作作为业余项目，借助 Astra 在不到一周的时间内完成了测试设备的设计。一家代工厂在不到一个月的时间内制造出了一小批原型。

要让设备达到可制造状态，仍然需要多轮审查和迭代。Astra 未能始终充分考虑制造商的生产限制、公差要求或装配所需的细节。这些不足正在帮助我们明确，未来的模型需要在哪些方面做得更好。

加速 OpenAI 硬件团队的工作

OpenAI 的硬件和基础设施团队使用 Codex 和 ChatGPT 创建并修改计算机辅助设计（CAD）模型、准备制造图纸、设置仿真，以及审查设计。这些工作涉及机器人和计算基础设施。自 2 月以来，按 token 数量衡量，硬件团队的模型用量已增长至原来的 23 倍。

“Codex 大幅加快了我们将想法转化为工程零件的过程。我们能更快地迭代 CAD 设计，将三维设计转化为可直接用于生产的二维图纸，并设置仿真和有限元分析（FEA）。这些工作所需的人工操作都大幅减少了。”

“作为系统硬件设计人员，我们使用 Codex 和 ChatGPT 梳理跨职能的设计约束、探索系统架构、在各类电子计算机辅助设计（ECAD）环境中开展工作，并进行全面的设计审查。如今，Codex 和 ChatGPT 已经成为工程和项目管理中可靠、全天候的合作伙伴。未来，它们有潜力发展成硬件专家团队，将电路板从概念一路推进到 Gerber 文件输出。”

“在建筑、工程与施工（AEC）以及建筑信息模型（BIM）领域，很多时间都花在重复建模、核对图纸与规格说明中的信息，以及协调不同专业之间的变更上。我们开始使用 Codex 自动处理常规任务、标记不一致之处，并将协调过程中发现的问题整理为清晰、可执行的事项。这让团队有更多时间评估设计方案和施工可行性。结果仍由建筑师、工程师和 BIM 专业人员审查并验证。”

衡量工程任务上的进展

我们也在衡量较新模型在结合编程与工程知识的任务上取得的进展。BenchCAD 2.0 测试模型能否重建三维零件和装配体，以及识别电路板中的连接。一个较新的内部模型取得了 0.875 的平均得分。相比之下，GPT‑6 Astra 在最高推理设置下的平均得分为 0.594。工程生命周期包含设计之外的许多其他环节。尽管如此，我们仍将这里的能力提升视为早期证据，表明 AI 模型有望加快专业工作流程中的迭代。

与行业合作方共同推进安全部署

我们正与少数行业合作方一起，在真实工程问题上测试这些能力。他们的工程师会审查模型输出的准确性和实际可用性。这有助于我们了解模型目前能支持哪些任务，以及要实现安全、可靠的使用，还需要改进哪些方面。

我们正在扩大与 Chip Ganassi Racing（CGR）的合作，探索 OpenAI 模型如何加快工程研发和原型制作。我们与其研发团队一起，测试将现有零件的三维扫描转换为可编辑 CAD 模型和二维制造图纸的工作流程。当原始设计文件不可用时，这尤其有帮助。

CGR 工程师会审查模型和图纸的准确性与可制造性。他们的反馈帮助我们识别模型在哪些地方可以减少人工工作，以及哪些地方仍需进一步改进。

“在把原始扫描数据转化为实体模型的过程中，这个模型很有帮助。我一直直接在 CAD 中使用 Codex。我给模型的反馈会直接应用到设计中，也可以直接进行手动微调。对我来说，这个过程变得更快，也更少需要亲手操作。”

我们还宣布与 Mazda 开展一项新的研究合作。我们的研究团队和前线部署工程团队正在与 Mazda 的空气动力学及碰撞安全工程师合作，探索 OpenAI 模型如何帮助开发和评估新的汽车设计。

这项工作利用气流和结构行为仿真，在兼顾造型与成本的前提下探索性能改进。我们将在未来几个月分享更多进展和结果。

GPT‑6 Astra 通过建立新的车头形状模型、模拟气流，并完善最有前景的设计，帮助 Mazda 的空气动力学工程师探索降低车辆风阻的方法。已获得 Mazda Motor Corporation 的使用许可。严禁在其他地方再次发布或重复使用。

“‘一定得长这样吗？’当我们找到一种能够改善气流的形状时，设计师经常这样问。通过探索和仿真数十种变体，Codex 中的 Astra 帮助我们理解哪些特征对空气动力学至关重要，以及设计师在哪些方面还有探索空间。因此，Astra 和与 OpenAI 的合作所带来的价值，不止于任务自动化和缩短开发周期。它正在帮助我们将 Mazda 独特的设计与空气动力学性能结合起来，而不必将任何一方视为需要妥协的对象。”
