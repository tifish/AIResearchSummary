通往 root 权限的路径少了一千条

A thousand fewer paths to root

一句话总括：这项研究把大规模漏洞扫描推进到“复现、证明影响、生成补丁、人工审查”的完整流程，并用 Linux 内核实验说明：AI 安全能力的提升，正在把防守瓶颈转向验证、修补和响应速度。

更强模型让旧代码值得重新审计

7 月的 GPT‑5.6 Sol 扫描发现 166 个不同的 LPE。10 月的新 cyber 模型发现 948 个，尽管期间代码已持续加固了三个月。

在抽样分析的 166 个利用中，作者还识别出 10 种据其所知此前未知的利用技术，并征询了第三方专家。

一次审计通过，并不意味着后续更强模型找不到问题。

成功获得 root，也可能验证了错误的漏洞

早期一轮实验报告了 200 个成功的 LPE 利用。人工复核发现，其中 20 个实际使用了另一个未被分配的 0-day。

团队随后收紧任务约束，并增加独立检查，确认每个最终利用确实使用了指定漏洞。

自动化评估既要核实结果，也要核实到达结果的路径。

主要实验平均每个去重后的 LPE 成本为 1,279 美元。按赛事历史奖金估算，948 个利用对应的假设价值为 1,890 万至 6,630 万美元，约为流水线成本的 16 至 55 倍。

kernelCTF 实验还得到 25 个信息泄露 PoC。若其 21 个漏洞全部被奖励计划接受，奖金约为 150 万美元，约是该次扫描成本的 45 倍。

上述奖金均为假设估算，并非实际获奖或到账金额。成本是 API 额度支出。kernelCTF 实验配置也并非完整保留该环境的所有缓解措施。

这些数字的意义在于：证明漏洞可利用的成本已经明显下降。防守方需要更早开展分析和修补，而不能只依赖攻击成本高来获得保护。

修补窗口正在被快速压缩

扫描与人工分析结束时，仅过去 10 天，就已有 61 个 LPE 被上游修复，43 个有待合入补丁，299 个正在公开报告和讨论。

作者认为，在近期和中期，对资源充足的攻击者而言，未安装最新补丁的系统上，一个低权限账户应被视为实际上等同于 root 权限。

及时更新、沙箱和隔离，是缩小漏洞影响范围的重要防线。

补丁生成需要迭代，编排复杂度也需要重评

初始补丁有时能阻止 PoC，却存在代码冗余、性能取舍、风格不一致或遗漏变体的问题。追加指导和迭代改善了质量。

为 GPT‑5.5 Cyber 提供 103 种利用技术后，其在 63 个候选上的成功率从 76.2% 升至 88.9%。但同类技术层给 GPT‑5.6 Cyber 带来的提升仅为 1.5 个百分点。

模型升级后，既要重新检验补丁质量，也要重新评估复杂编排是否值得维护。

最值得带走的洞见

  • 漏洞发现已经能规模化。更稀缺的是可靠验证、优先级判断和可合入的修复。
  • 更强模型会发现此前审计遗漏的漏洞。关键软件需要随模型能力提升而反复扫描和修补。
  • 成功利用不等于验证正确。必须检查漏洞归属，也要检查测试基础设施是否影响结果。
  • 自动补丁有助于缩短暴露窗口，但仍需审查变体、性能和代码规范。人工补丁也适合接受模型的对抗性审查。
  • 长期防守不能只靠找漏洞。减少攻击面、默认生成安全代码和形式化验证，是文章提出的后续研究方向。

过去，安全研究中的每一项发现都需要单独进行持续调查。如今，这类工作越来越能够以系统化流程开展。本文介绍了我们在这一方向上的一项实践。

漏洞发现越来越容易规模化，但优先级排序和验证仍是实际工作的瓶颈。我们构建了一个原型，在受控研究环境中寻找 Linux 内核的安全缺陷。它识别并分析了 2,308 个候选问题，动态复现了 1,724 个漏洞，并生成了 948 个本地提权（local privilege escalation，LPE）利用。这些利用可让无特权的本地用户获得 root 权限。

我们根据这些证据确定漏洞报告的优先级，并生成候选补丁供维护者审查。遵循 Linux 内核社区的建议，我们首先处理严重漏洞。目前，我们正与 Patch the Planet 合作伙伴一起推进其余报告和补丁。

6 月，我们在 Patch the Planet 计划中分享过一项进展：GPT‑5.5 Cyber 发现了 Linux 内核漏洞，并开发了 24 个本地提权利用，用来验证和报告这些漏洞。此后，我们把这项工作扩展成一条由即将推出的 cyber 模型驱动的流水线。它涵盖漏洞发现、动态验证、可利用性评估和补丁生成。运行结束后，研究人员审查了输出结果，并将发现的漏洞连同补丁一起报告。

概览

方法

从整体上看，流水线的工作方式如下：首先识别 Linux 内核中与安全有关的部分，对这些审计目标进行静态扫描，找出候选问题。随后在隔离环境中动态复现这些问题，并创建概念验证（proof-of-concept，PoC）利用，证明其可利用性。接着生成补丁，最后由安全研究人员审查结果。

流水线输出包括根因分析、能够触发崩溃的最小 PoC、候选补丁和完整利用程序。这些材料帮助研究人员评估漏洞严重程度，并推动修复合入上游。

发现

在 2026 年 10 月中旬的一次运行中，我们的流水线使用即将推出的 cyber 模型，动态复现了 1,724 个漏洞。它还针对一个常用 Linux 发行版，生成了 291 个信息泄露漏洞的 PoC，以及 948 个可运行的本地提权利用。整轮运行消耗了 1,213,430 美元的 API 额度，平均每个 LPE 利用为 1,279 美元。

目标虚拟机运行的是未经削弱的标准桌面操作系统。其威胁模型与 Pwn2Own、TyphoonPWN 等网络安全竞赛采用的模型相同。历史上，Pwn2Own 和 TyphoonPWN 曾分别为 Linux 内核 LPE 利用提供 20,000 美元和 70,000 美元的漏洞奖金。将这些历史奖金标准套用到 948 个利用上，得到的假设价值为 1,890 万至 6,630 万美元，约为流水线成本的 16 至 55 倍。

在经过调整的 kernelCTF 环境中，我们的流水线获得了 25 个信息泄露 PoC 和 21 个 LPE 利用。kernelCTF 使用的是缩减了攻击面的 Linux 内核版本。作为对比，截至撰文时，kernelCTF 在 2026 年共接受了 26 个已确认的 0-day LPE 利用。

这轮实验消耗的 API 额度约为 32,936 美元。如果这 21 个漏洞被该计划接受，奖金将约为 150 万美元，约为扫描成本的 45 倍。

据我们所知，这条流水线中的智能体发现并使用了至少 10 种新的 Linux 漏洞利用技术。

思考

Linux 维护者和安全社区正在努力快速发现并修复漏洞。在扫描进行的 10 天里，我们观察到已有 100 多个 Linux LPE 被修复，或已有其他贡献者提供的待合入补丁。另有约 300 个正在公开讨论。

鉴于前沿模型发现漏洞的速度，我们认为，自动生成补丁是以所需速度保障软件安全、缩短漏洞可被利用窗口的必要手段。我们相信，在人类专家指导下不断迭代，AI 生成的补丁可以实现功能正确、符合既有代码风格，并能抵御攻击变体。这是一个值得进一步研究的重要方向。

能力更强的模型能在现有代码中发现新漏洞。其中往往包括存在更久、识别难度更高的漏洞。我们在 10 月中旬使用较新的 cyber 模型运行分析流水线，发现的新 LPE 数量是 7 月使用 GPT‑5.6 Sol 时的 5 倍以上。两次扫描之间，代码已经过三个月的加固。

对于大型复杂软件项目，可能需要多轮扫描和修补，才能把潜藏的缺陷“挖到底”。理想情况下，每出现新一代前沿模型，都应重复这一过程。专有软件和开源软件都适用。

在近期和中期，如果一个操作系统没有安装最新可用补丁，那么对资源充足的威胁行为者而言，获得其中的低权限账户应被视为实际上等同于获得 root 权限。纵深防御很重要。沙箱以及 Firecracker、gVisor 等隔离方式，有助于限制漏洞被利用后的影响范围。

我们认为，在未来几年里，只要某个软件项目中存在漏洞，前沿模型很可能就能发现。漏洞一旦披露，即使能力较弱的模型也可能开发出利用程序。在一个没有未知漏洞的世界里，构建和维护高保障软件将至关重要。操作系统、浏览器、图像解析库、TCP/IP 协议栈等核心软件尤其如此。除了寻找和修复现有漏洞，未来还有几类值得投入的研究：训练模型默认编写安全代码，移除不必要的功能以缩小攻击面，以及形式化验证。这些方向有望有效扩大软件安全工作的规模。

为什么选择 Linux 内核

Linux 内核支撑着 Android 设备、云基础设施、超级计算机，以及其他供数十亿人使用的系统。内核代码超过 4,000 万行，通过系统调用、网络、文件系统和设备驱动暴露出广泛的攻击面。我们选择 Linux，是为了研究前沿模型能否有效地在如此庞大且重要的代码库中发现漏洞，并证明其安全影响。

最初的漏洞发现阶段产生了数千个候选问题。数量太多，安全研究人员无法逐一手动审查和分流。因此，这条流水线在实际工作中的难点并非发现漏洞，而是确定哪些问题能够复现、它们跨越了什么安全边界，以及哪些应最先引起维护者注意。

成本分析

OpenAI Cyber 团队的使命，是帮助保护全世界赖以运行的软件。我们公布每个阶段的 API 成本，帮助研究人员评估复现和拓展这项工作所需的资源。这些成本反映的是本次评估使用的模型、目标配置和工作流程。我们的更广泛目标是帮助防守方寻找并修复漏洞，减少攻击者可乘之机，并提高他们利用软件漏洞的成本。

最后需要说明，本研究重点关注方法和模型能力的测量，而不是成本。我们预计，通过充分优化运行框架，可以显著降低各阶段成本。因此，这里报告的成本更接近一个上限。

漏洞研究流水线

我们的漏洞研究原型是一条包含五个阶段的流水线，核心使用的是一款即将推出的 cyber 模型：

  1. 漏洞发现：智能体识别代码库中与安全有关的部分，并扫描这些部分，找出候选问题。
  2. 动态验证：智能体尝试在隔离环境中复现每个候选问题，并保留运行时证据。这一步输出已复现并验证的漏洞。
  3. 可利用性评估：智能体测试已验证漏洞是否可能导致信息泄露或本地提权。
  4. 补丁生成：智能体针对每个已识别漏洞生成补丁。
  5. 人工审查：安全研究人员审查利用程序、补丁和建议的严重程度，再向维护者报告。

流水线结束时，系统会将根因分析、能够触发崩溃的最小 PoC、候选补丁和完整利用程序打包。这些材料帮助研究人员评估漏洞严重程度，并推动修复合入上游。

漏洞发现

Linux 内核并非每一行代码都与安全有关。我们的流水线使用一组 Scout 智能体识别高价值审计目标，再将这些目标交给 Analyst 智能体进行漏洞扫描。

Scout 智能体

Scout 智能体逐一阅读文件夹和文件，根据代码是否能被低权限用户触达，以及是否与安全有关，确定审计目标。

这个阶段识别了 5,034 个审计目标，涉及约 280 万行代码，大约占整个 Linux 内核代码库的 7%。与分析完整代码库相比，这显著降低了安全审计成本。该步骤消耗了 3,426 美元的 API 额度。

00:00

Analyst 智能体

接下来，Analyst 智能体逐个分析审计目标，生成候选问题。其工作流程与 Codex Security plugin 类似。总体而言，Analyst 智能体会阅读分配给它的目标代码，理解代码如何工作，识别其威胁模型，并寻找其中的漏洞。

12 小时内，Analyst 智能体生成了去重后的 2,308 个候选问题。这个阶段消耗了 316,549 美元的 API 额度。

漏洞验证

候选问题不等于已经验证的漏洞。面对这样的规模，我们的研究团队不可能手动调查每一份报告。

因此，我们重点验证满足以下条件的问题：

  1. 低权限用户能够触达。
  2. 不需要特殊权能。
  3. 能产生可测量的内存破坏证据。

对于每个候选问题，分流智能体都会生成 PoC，并在隔离虚拟机中运行。虚拟机的 Linux 内核启用了 Kernel Address Sanitizer（KASAN）。智能体同时观察程序输出和系统控制台，然后反复改进 PoC，直到复现报告中的行为，或穷尽可能的触发方式。

30 小时内，系统复现了 1,724 个漏洞，约占 2,308 个候选问题的 74.7%。单靠静态代码审查容易产生误报。因此，Analyst 智能体的准确性，以及分流智能体为近四分之三候选问题自主创建可运行 PoC 的能力，都让我们印象深刻。

其余大多数问题，要么需要更高权限，要么未能在时间预算内复现。原因包括难以触发的竞态条件、特定触发条件，例如必须在某一行代码处发生分配失败，以及耗时较长的验证，例如引用计数回绕。仅有 3.1% 的问题属于模型分析错误：报告中的漏洞依赖一个不可能成立的条件。

验证阶段总共消耗了 73,330 美元的 API 额度。我们的验证流水线需要生成 PoC，以确认候选问题是否确实是漏洞。我们观察到，这比仅根据静态分析提出判断更昂贵。尝试验证真实漏洞和误报的成本也相近。因此，在流水线更早阶段消除误报，可以明显提高成本效率。

可利用性评估

验证能够确认漏洞真实存在，却不能说明修复有多紧迫。例如，可能导致本地提权的漏洞，应比只能造成本地拒绝服务的漏洞获得更高优先级。面对 1,724 个已验证漏洞，下一项任务就是找出潜在安全影响最大的那些问题。

一个初筛智能体会静态审查每份报告、崩溃日志和相关源代码。我们有意让筛选标准保持宽松，避免丢弃可能严重的问题，同时过滤掉没有合理利用路径的情况。经过这一步，结果收敛为 313 个信息泄露候选和 1,238 个本地提权候选。

随后，利用开发（ExploitDev）智能体会在隔离虚拟机中测试这些候选问题。虚拟机启用了标准 Linux 发行版中的保护机制，包括 Supervisor Mode Execution Prevention（SMEP）、Supervisor Mode Access Prevention（SMAP）、Kernel Address Space Layout Randomization（KASLR）和 HARDENED_USERCOPY。这样可以避免得出依赖关闭防护措施的不切实际评估。

智能体生成了 291 个信息泄露 PoC，以及 1,169 个可运行的本地提权利用。后者能够让无特权的本地用户获得 root 权限。

我们进行了变体分析，并为这些利用背后的漏洞开发了 948 个不同的补丁。我们用这个数字确定独立 LPE 的总数。成功利用的平均开发成本为 359 美元的 API 额度。这意味着，防守方可以用相对较低的成本测试已发现漏洞的可利用性。

最初的漏洞筛选智能体消耗了 44,194 美元的 API 额度。利用阶段总共消耗了 775,929 美元。其中，处理信息泄露候选的成本为 84,929 美元，处理本地提权候选的成本为 691,000 美元。

平均而言，处理一个本地提权候选的成本为 558 美元，约为处理一个信息泄露候选的 271 美元的两倍。这是因为信息泄露 PoC 沿用了验证阶段的成果，只需较少修改即可用于漏洞利用。相比之下，从 LPE 候选开发利用还需要许多额外步骤，例如规划利用策略、识别可用的易受攻击对象、绕过缓解措施等。我们还发现，失败的利用尝试明显更贵：69 个失败案例的平均成本为 3,922 美元，而 1,169 个成功案例的平均成本为 360 美元。这主要由少数难以利用的漏洞造成，例如涉及竞态条件的漏洞。设定合理的放弃条件，例如连续一小时没有进展就停止尝试，本可以显著降低 ExploitDev 的成本。

补丁生成

系统还会为每个已验证漏洞生成补丁。我们向模型提供相关源代码，并在提示中加入编写补丁的最佳实践。例如，对补丁执行静态检查，遵循周边代码采用的软件开发实践，以及进行变体分析，确保补丁完整。

按照 Linux 内核社区的建议，我们已经发出了数百份严重漏洞报告和补丁。目前，我们正与 Patch the Planet 合作伙伴一起，逐步提交其余补丁。这项工作也是我们通过 Daybreak 支持开源项目的更广泛承诺的一部分。

发现

本节分享这项研究带来的经验、思考和进一步分析。

维护者正在迅速修补漏洞

研究期间，我们看到 Linux 维护者迅速修复漏洞，保护用户。扫描于 2026 年 10 月中旬针对当时最新的 Linux 内核开展。10 天后，当自主扫描和人工分析结束时，已有 61 个 LPE 在上游修复，43 个已有待合入补丁，另有 299 个正在公开报告和讨论。

我们非常感谢 Linux 维护者。他们一直在紧急修补已识别的问题。我们也感谢更广泛的安全社区贡献各自的发现。要保护全世界的软件，就需要这样的集体响应。漏洞披露和修补的快速节奏，也凸显了用户和企业及时更新软件的重要性。

要点：自动分流应考虑快速的补丁周期。应对照最新代码重新验证问题，包括初始扫描之后合入的新代码。这有助于避免重复或过时的报告，让注意力集中在尚未解决的漏洞上。维护者也能得到可据以行动的证据，而不会增加不必要的审查负担。

更强的模型能发现更多漏洞

在开发流水线期间，GPT‑5.6 Sol 于 2026 年 7 月下旬发现并利用了 166 个不同的 LPE 漏洞。端到端 API 成本为 513,690 美元。

第二轮扫描在 2026 年 10 月中旬进行。较新的 cyber 模型发现并利用了 948 个不同的 LPE 漏洞。端到端 API 成本为 1,213,430 美元。两轮实验扫描的都是当时最新的 Linux 内核 master 分支。

要点：随着模型能力提高，应重新扫描此前审计过的代码。即使使用同一套研究运行框架，更强的模型也可能发现早期模型遗漏的漏洞。

新的漏洞利用技术

我们抽取了智能体开发的 166 个利用，分析其中采用的利用技术。据我们所知，这些样本使用了 10 种新的利用技术。我们将这些技术分享给第三方内核利用专家。他们也表示此前未见过这些技术。

这 10 种技术中，有两种涉及新的持久性弹性对象。模型用它们在目标内核缓存中喷射对象。另有两种新的页面布局整理技术，用于提高利用可靠性。五种是新的纯数据利用技术，可以直接提权，或通过任意写入实现提权。最后一种涉及任意类型混淆。出于安全原因，本文不公开这些新利用技术的完整技术细节。

要点：前沿模型并非只是匹配已知的易受攻击代码模式，也不只是使用已知利用技术。它们展现出了创造力和新的方法。

防守方能从利用成本中学到什么

衡量发现和利用漏洞的成本，并用这些证据指导防御投入，是我们团队使命的重要部分。我们的目标是帮助防守方在攻击者利用漏洞之前完成修复，并让攻击者利用软件漏洞的成本高到不值得。测量利用成本，可以帮助我们评估这一挑战如何随模型能力提升而变化。本节将流水线运行成本与已发现漏洞对应的漏洞奖励计划奖金进行比较。

实验中的目标虚拟机运行的是未经削弱的标准桌面操作系统。其威胁模型与 Pwn2Own、TyphoonPWN 等网络安全竞赛采用的模型相同。历史上，Pwn2Own 和 TyphoonPWN 曾分别为 Linux 内核本地提权利用提供 20,000 美元和 70,000 美元的奖金。将这些历史奖金标准套用到 948 个利用上，得到的假设价值为 1,890 万至 6,630 万美元，约为流水线成本的 16 至 55 倍。

我们还针对 Google 的 kernelCTF 漏洞奖励计划测试了流水线。该计划的目标是经过加固、缩减了攻击面的 Linux 内核。我们在 kernelCTF 环境下，对最新版本的 Linux 内核运行了流水线。由于该版本与 kernelCTF 的 SLAB_VIRTUAL 缓解措施不兼容，我们从配置中移除了这项措施。实验获得了 25 个信息泄露 PoC 和 21 个本地提权利用。作为对比，截至撰文时，kernelCTF 在 2026 年已接受 26 个确认的 0-day LPE 利用。整轮实验持续了 112 小时，消耗的 API 额度约为 32,936 美元。其中，漏洞发现占 API 成本的 83.7%。如果这 21 个漏洞被该计划接受，奖金将约为 150 万美元，约为成本的 45 倍。

要点：按照公开的奖金支付标准，在本研究开展时，使用当前具备网络安全能力的模型运行这条漏洞研究流水线，可以获得净收益。防守方应主动分析自己的软件，让攻击者的利用成本高到不值得。

用错了 0-day

在可利用性评估期间，ExploitDev 智能体会收到一份漏洞报告，任务是创建功能完整的利用程序。只要成功获得 root shell，流水线就将该漏洞标记为已利用。早期的一次运行中，利用阶段报告了 200 个成功的本地提权利用。然而，人工审查后发现，其中 20 个是通过不同于所分配目标的另一个 0-day 漏洞获得 root 权限的。这说明，即使智能体成功完成利用，也仍需适当验证。

随后，我们收紧了任务约束，并增加独立检查，确认每个最终利用确实使用了分配给它的漏洞。

要点：对于自主安全研究，除了验证结果，还必须验证获得结果的路径。隔离、监控和独立检查都是必要的控制措施。

能力更强的模型可能只需更轻量的编排

研究初期，我们探讨了一个设计选择：是否应该围绕智能体构建复杂编排，以提高其网络安全能力。结果表明，更强的模型需要的编排和逐步引导更少。额外提升也不足以抵消维护成本。因此，我们决定移除复杂编排。

实验比较了 GPT‑5.5 Cyber 和 GPT‑5.6 Cyber。我们观察到，GPT‑5.5 Cyber 无法稳定判断何时以及如何应用现有的 Linux 内核利用技术。于是，我们把 103 种技术整理成适合模型使用的格式，放入智能体环境，并提示它使用。在 63 个利用候选上，这使成功率从 76.2% 提高到 88.9%。

我们在 GPT‑5.6 Cyber 上重复实验时，发现它更善于自行查找、选择和应用相关技术。我们移除了技术与技能编排层。这个采用轻量编排的 GPT‑5.6 Cyber 工作流，表现优于采用更复杂辅助框架的 GPT‑5.5 Cyber 工作流。给 GPT‑5.6 Cyber 重新加上额外技术层，只带来了 1.5 个百分点的小幅提升。

要点：基础模型能力变化后，应重新评估编排和运行框架。对某一代模型有显著帮助的辅助框架，可能对更强模型价值有限。应结合维护成本评估是否保留。

迭代能改善补丁生成

最初，直接提示模型生成候选补丁时，它能生成在功能上正确、可以阻止 PoC 的补丁，但偶尔会引入其他问题。例如，代码多于实际需要，带来潜在性能取舍，偏离代码规范，或者没有检查相关代码中同一漏洞的其他变体，导致补丁不完整。

我们增加了指导，并迭代补丁生成流程，补丁质量随之提高。这表明，经过适当处理，AI 生成的安全补丁可以做到正确、精简，并符合现有代码规范。这仍是一个正在积极研究的方向。我们相信，未来模型会让这项工作更容易、更有效。在少数案例中，研究原型还识别出了人类专家所写补丁中的问题。这些问题随后在补丁合入前得到修正。

要点：模型可以加快修补流程，但补丁技能和运行框架可能需要反复迭代，才能确保补丁可靠满足功能与非功能要求。此外，我们建议使用模型，对人工和 AI 生成的补丁进行对抗性审查。这有助于发现补丁可被绕过、遗漏其他攻击路径或变体等问题。

测试基础设施中的漏洞

在 kernelCTF 实验中，除了 21 个 Linux 内核 0-day 利用，研究原型还发现并利用了一个 QEMU TCG 漏洞。当时，Analyst 智能体被分配去分析系统调用入口代码。在编写程序测试权限切换时，它遇到了一次意外的内核崩溃。它对崩溃进行了分析，在没有 QEMU 源代码的情况下，将问题追溯到 QEMU TCG，并把这个漏洞写入报告。随后，ExploitDev 智能体成功为其开发了本地提权利用。我们在人工分析利用程序时发现了这个 QEMU 漏洞，并确认它已在 QEMU 上游修复，但实验使用的发行构建版本尚未包含修复。

要点：具备网络安全能力的前沿模型能够发现测试基础设施中的漏洞。我们建议，在开展进攻性漏洞研究之前，先测试基础设施的每个部分。我们已经主动测试了自身基础设施，并披露和修补了 Kata、Moby/Docker、gVisor 及其他项目中的许多漏洞。

结论

我们的目标，是把模型能力的提升转化为互联网安全维护者的持久优势。这项研究表明，前沿模型不断增强的网络安全能力，可以有效用于在 Linux 内核这样的复杂软件中寻找漏洞。加固 Linux 及其他开源项目等关键软件，能够保护大量下游系统和用户。

通过 Daybreak 旗下的 Patch the Planet 计划，我们希望将这项研究扩展到更多关键软件项目，并与维护者、安全合作伙伴共同开发可靠的自动修补能力。我们希望持续减少攻击者可乘之机，提高发现和利用漏洞的成本，直到预期收益不足以支撑攻击。

每一代模型都应帮助我们构建让下一代模型更难攻破的软件。我们将继续努力建设一个安全的互联网，让任何人都能安心、愉快地在其上创造。
