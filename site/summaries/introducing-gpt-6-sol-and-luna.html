事实性改善，不等于日常错误率减半

在内部事实性评测中，Sol 的错误约为前代的一半。Luna 在较高推理强度下达到 GPT-5.6 Sol 的水平，成本约为其百分之一。

这表明较低价格与事实可靠性可以同时改善。但评测选取的是用户曾标记错误的对话，不能把结果直接外推为日常使用的错误概率。

更实用的协作，还包括少说空话

文章称，Sol 和 Luna 延续了 Astra 的沟通改进：表达更清楚，术语更少，低价值细节更少，回答也略短。

内部对齐评测还显示，两者在编程工作中作出误导性陈述的比例低于前代。可信赖的协作不仅需要做对任务，也需要如实交代检查了什么。

高难度评测有明确的解释边界

事实性样本并不代表典型使用。编程欺骗评测也刻意选择容易诱发不诚实行为的任务，并使用最高推理强度。正文没有给出该项评测的具体欺骗率。

此外，GPT 的评测来自研究环境或 API，竞品结果取自公开报告。系统提示和可用工具等差异，可能影响实际可比性。

缓存让成本优化延伸到整个工作流程

除了降低 token 单价，GPT-6 还提高了默认缓存命中率。缓存输入读取可享受 90% 折扣。开发者现在可以调整推理强度或启停工具，同时保留此前上下文的缓存复用。

复用可以被观察和调整

  • Prompt Caching Dashboard 显示缓存输入量及其变化。
  • 诊断工具帮助定位未命中缓存的原因。
  • 显式断点让开发者决定缓存提示前缀的结束位置。

GitHub 提供了大规模使用结果

GitHub 报告称，过去几个月，这些改进覆盖了对 OpenAI 模型的数十亿次请求。需要重新处理的提示 token 占比下降了 超过 50%，帮助 Copilot 更快响应。

这一结果衡量的是重新处理的 token 占比，并不等同于总账单下降超过 50%。

持续运行智能体时，模型单价只是成本的一部分。上下文能复用多少，也会影响成本和响应速度。

发布范围先覆盖 Work、Codex 和 API

按文章所述，模型自 2026 年 9 月 22 日起向 Plus、Pro、Business、Enterprise 和 Edu 用户开放，入口为 ChatGPT Work 和 Codex。Free 和 Go 用户可在桌面应用中使用 Luna。

文章发布时，两款模型尚未在 Chat 中提供。API 名称为 gpt-6-sol 和 gpt-6-luna。ChatGPT 内采用当天逐步开放的方式，因此发布当天不同用户看到的可用状态可能不同。

最值得带走的洞见

  1. 更低成本才是这次发布的主线。Sol 和 Luna 将部分高端能力带到更适合反复使用的价格区间。
  2. 比较模型时，要同时看得分、推理强度和任务成本。单看模型名称或 token 单价，都不足以复现文章中的优势。
  3. 缓存是长期任务的重要变量。调整推理强度和工具时仍能复用上下文，让动态工作流程有了更多优化空间。
  4. 可靠性改善需要连同样本限制一起理解。刻意筛选的错误或欺骗场景，不能代表普通用户遇到问题的频率。
  5. Astra 仍保留最高能力的定位。模型选择的重点，是让任务要求与成本预算匹配。

本月早些时候，我们推出了 GPT-6 Astra。它是全球智能水平最高、对齐表现最好的模型。要求最高、最重要的项目，仍然需要充分发挥 Astra 的能力。不过，不同工作的规模、节奏和预算各不相同。

因此，我们推出 GPT-6 Sol 和 GPT-6 Luna，进一步扩展 GPT-6 模型家族。GPT-6 Astra 带来了新一代智能。Sol 和 Luna 则进一步提升了成本效益，让更多人受益于这一代智能。我们采用了与 GPT-6 Astra 相近的方法来训练 Sol 和 Luna。支撑 Astra 在专业工作、事实准确性、编程、计算机操作和对齐方面达到领先水平的技术进展，由此进入了速度更快、价格更低的模型。

在成本与智能水平构成的曲线上，GPT-6 系列处于领先位置。各档模型都具备出色能力，底层基础设施则能高效地大规模提供这些能力。缓存和推理方面的改进降低了我们的服务成本。我们将这些节省直接让利给用户和客户：与 GPT-5.6 的促销价格相比，Sol 和 Luna 的 API 价格降低了 50%。这些改进共同作用，让先进 AI 能以切实可行的成本，应用于更多日常任务和大规模应用。

整个模型家族的能力提升

GPT-6 Sol 和 Luna 为你已经熟悉并使用的模型带来了更高的智能水平和成本效益。这些提升覆盖了完成复杂工作时最实用的能力。

专业工作

GPT-6 Sol 能够承担高难度工作任务。更高的使用限额和更低的成本，也让你有更多空间反复尝试。与价格相近的竞品模型相比，它提供了更强的智能和更好的结果。

AutomationBench 测试跨应用的业务工作流程。在这项评测中，xhigh 推理强度的 GPT-6 Sol 超过了 max 推理强度的 Claude Opus 5，而每任务成本仅为 Opus 5 的 9%。在 high 推理强度下，GPT-6 Luna 比前代提高了 5.4 个百分点，每任务成本则降低了 58%。

在 AutomationBench 1.0.6（在新窗口中打开）中，AI 智能体使用 47 种工具完成端到端工作流程。任务覆盖销售、营销、运营、支持、财务和人力资源。Claude Fable 5.1 的数据点低估了其实际成本，因为它没有计入回退使用 Opus 5 的成本。约 40% 的任务发生了这类回退。

GPT-6 Sol 还以低得多的成本超过了 Claude Fable 5.1，甚至优于低推理强度的 GPT-6 Astra。

事实准确性

回答是否有用，取决于事实是否准确。我们正在持续提升事实可靠性。我们的内部事实性评测使用经过去标识化处理的真实对话。这些对话中，用户曾指出模型出错。在该评测中，GPT-6 Sol 的错误数量约为前代的一半。它以低得多的成本，接近了 Astra 的可靠性水平。GPT-6 Luna 也有显著进步。在较高推理强度下，它能够达到 GPT-5.6 Sol 的水平，成本约为后者的百分之一。

这里的事实性评估使用了经过去标识化处理的 ChatGPT 对话。在这些对话中，用户曾标记此前模型给出的事实错误。这些容易诱发错误的对话并不代表典型使用场景。在典型使用中，事实错误更少见。评分没有控制回答长度。不过，我们对不同回答详略程度的测试表明，评分几乎不受回答长度影响。

编程

今年，编程智能体开始处理前所未有的复杂任务。任务范围更广，持续时间也更长。在 OpenAI，内部使用量呈指数级增长。如果按 API 价格折算，研究人员每天的 token 使用额，中位数已超过 600 美元，第 90 百分位已超过 7,000 美元（《研究加速：OpenAI 内部视角》）。随着编程智能体承担更长、更具挑战性的任务，持续使用的成本变得更加重要。GPT-6 Sol 和 Luna 将强大的编程表现与更低的 API 价格结合起来。开发者因此有更多迭代空间，团队也更有信心将更具挑战性的工作交给 Codex。

FrontierCode 评估编程智能体提交的修改，是否已经达到可以合并进真实代码库的标准。在这项评测中，GPT-6 Sol 相比 GPT-5.6 Sol 有显著提升。它还能够以低得多的成本，达到 xhigh 推理强度的 Claude Fable 5.1 的水平。

在 FrontierCode 1.1 Main（在新窗口中打开）中，AI 智能体编写的代码不仅按正确性评分，也按“可合并性”评分。后者包括测试质量、是否严格控制修改范围、代码风格，以及是否遵守代码库规范等。

DeepSWE v1.1 测试模型处理真实代码库中复杂软件工程任务的表现。max 推理强度的 GPT-6 Sol 得分为 68.8%。与 Claude Fable 5 在该评测中的最高分相比，它只低 1.1 个百分点。Fable 5 的最高分是在 xhigh 推理强度下取得的 69.9%。GPT-6 Sol 的每任务成本约低 80%。

max 推理强度的 GPT-6 Luna 得分为 66.6%。这与 medium 推理强度的 Claude Opus 5 和 Fable 5 相近。在这些比较中，Luna 的每任务成本比 Opus 5 低 93%，比 Fable 5 低 96%。

在 DeepSWE 1.1（在新窗口中打开）中，AI 智能体需要解决原创的长程软件工程任务。

计算机操作

GPT-6 Astra 仍然是全球计算机操作能力最强的模型。与此同时，GPT-6 Sol 和 Luna 相比前代提供了更高的成本效益。在 OSWorld 2.0 offline 上，xhigh 推理强度的 GPT-6 Sol 与 medium 推理强度的 Claude Opus 5 得分相近，分别为 60.5% 和 60.3%。Sol 的每任务成本约低 80%。GPT-6 Luna（max）能够超过 GPT-5.6 Sol（medium），成本仅为后者的十分之一。

在 OSWorld 2.0（在新窗口中打开）中，AI 智能体尝试完成长程计算机操作流程。任务涵盖日常生活和专业工作。我们报告的是 v2026.08.08 版本离线集上的部分奖励得分。

改进智能体和长对话的缓存

除了降低 token 价格，我们还在帮助基于 GPT-6 开发应用的开发者，进一步节省复用上下文的成本。我们改进了 GPT-6 的提示缓存（prompt caching），使其默认缓存命中率更高。这能帮助智能体复用更多上下文，更快地响应，并在读取缓存输入 token 时享受 90% 折扣。

开发者也有了更多衡量和优化缓存表现的方法：

  • 监控与诊断。Prompt Caching Dashboard（在新窗口中打开）会显示有多少输入被缓存，以及缓存量如何随时间变化。诊断工具（在新窗口中打开）则帮助开发者了解哪些缓存机会被错过，以及应该如何修正。

  • 调整推理强度和工具可用性，不再导致缓存失效。遇到更难的任务时，可以提高推理强度（在新窗口中打开）。后续问题较简单时，则可以降低强度。你也可以根据智能体需求的变化，启用或停用工具（在新窗口中打开）。这两类调整现在都会保留此前的上下文，供缓存复用。

  • 优化需要缓存的前缀。显式断点允许开发者选择缓存提示前缀的结束位置。这让开发者能够更精细地控制缓存复用，并有望改善性能。

GitHub 报告称，过去几个月，在向 OpenAI 模型发出的数十亿次请求中，这些改进使需要重新处理的提示 token 占比下降了超过 50%。这帮助 Copilot 更快地作出响应。

持续改进对齐

GPT-6 Sol 和 Luna 延续了 Astra 引入的对齐工作。Astra 是我们迄今对齐表现最好的模型。在我们的对齐评测中，Sol 和 Luna 都优于各自的 GPT-5.6 前代。其中，它们对自身编程工作作出误导性陈述的比例有所降低。

下面的评测刻意测试具有挑战性的情境，并不衡量典型使用中的失败率。完整结果请参阅系统卡（在新窗口中打开）。

在我们的内部编程欺骗评测中，AI 智能体接到的任务经过专门挑选，目的是诱发不诚实行为。在典型使用中，欺骗行为要少见得多。欺骗率衡量的是：所有回答中，被检测出存在任何欺骗行为的回答所占比例。推理强度设为最高。

开放范围

从今天起，所有 Plus、Pro、Business、Enterprise 和 Edu 用户，都可以在 ChatGPT Work 和 Codex 中使用 GPT-6 Sol 和 GPT-6 Luna。Free 和 Go 用户可以在桌面应用中使用 GPT-6 Luna。这些模型尚未在 Chat 中提供。在 OpenAI API 中，它们的名称分别为 gpt-6-sol 和 gpt-6-luna。

为了保持服务对所有用户的稳定性，我们计划在今天逐步向 ChatGPT 用户开放这些模型。如果你在 ChatGPT Work 或 Codex 中还看不到新模型，请稍后再试。

GPT 的评测在我们的研究环境中进行，或通过我们的 API 完成。由于系统提示、可用工具等存在差异，输出可能与生产环境中的 ChatGPT 略有不同。竞品模型的评测结果来自公开报告。当没有 Claude Fable 5.1 的得分时，我们使用了 Claude Fable 5 的得分。
